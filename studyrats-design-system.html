Design System StudyRats

Tokens, componentes e telas do MVP, construídos a partir da sua tela de login e do Documento de Requisitos (MVP-01 a MVP-13). O laranja marca a ação e o progresso, o verde marca meta cumprida, e o cinza deixa o resto quieto.

Versão 1.0 React + CSS puro Tema claro

Fundamentos

Tudo vira variável CSS. Os nomes que já existem no seu login (--brand-orange, --card-bg, --border-color…) continuam valendo, então nada do que você já fez quebra. Clique em uma cor para copiar o valor.

Marca e neutros

Extraídos da tela de login: preto #1a1a1a nos textos e no logo, laranja #f2a900 nas ações, cartão #f4f4f5 e borda #e2e2e5.

Escala de laranja e cinza

Laranja (use 500 para fundo, 600 no hover, 800 para texto)

Cinza

Feedback

Cada estado tem fundo suave, texto escuro, borda e uma cor sólida para ícones e botões. Verde significa sempre "cumprido" (meta batida, sessão salva).

Cores de disciplina

Seis cores atribuídas pela ordem de cadastro. Fica só no front-end (índice da disciplina módulo 6), então não exige campo novo no banco. Evitam o laranja da marca para não confundir com ação.

Contraste

Calculado ao vivo (WCAG). Dois pontos merecem atenção na referência atual: o link "Criar conta" em laranja e o cinza de apoio sobre o cartão cinza. Por isso o sistema traz --orange-800 para texto laranja e --text-muted-strong para texto pequeno.

Tipografia

Fonte do sistema (a mesma do seu CSS atual): leve, instantânea e sem dependência externa. A personalidade vem do peso: 800 no logo, títulos e números; 600 em rótulos; 400 no texto corrido. Números usam tabular-nums para o cronômetro não "dançar".

Espaçamento

Base de 4px. Dentro de cartão use 20px (--space-5), entre cartões 16px, entre seções de uma página 24px.

Bordas

Sombras

Sombras são raras: a maioria dos cartões usa só a borda. Sombra aparece em coisas que flutuam (card de login, menu, modal, toast).

Componentes

Cada componente é uma classe (ou duas, com modificador). Todos têm estado de foco visível, e os desabilitados ficam a 60% de opacidade, como o botão do seu login.

Botões

.btn + .btn--primary | --dark | --secondary | --ghost | --danger | --danger-outline. Tamanhos --sm e --lg, e --block para largura total. Use um único primário por tela.

Campos de formulário

.field agrupa .label, .input (ou .select) e .field-hint / .field-error. Fundo sempre branco, mesmo quando o navegador faz autofill (aquele azul claro do print do login vem do navegador, e o sistema neutraliza).

Alertas e toast

.alert--info | --success | --warning | --error | --brand. Mensagens de erro dizem o que aconteceu e o que fazer, sem pedir desculpa. O toast confirma uma ação com o mesmo verbo do botão ("Excluir" gera "Sessão excluída").

Como usar no projeto

O arquivo studyrats-design-system.css contém tudo acima e também as classes auth-* que o seu login já usa, então você pode trocar o CSS atual por ele sem mexer no Login.jsx.

1. Importar uma vez

// src/main.jsx
import "./styles/studyrats-design-system.css";

2. Layout das páginas logadas

<div className="app-shell">
  <Navbar />
  <main className="page">
    <div className="page__header">
      <h1 className="page__title">Metas</h1>
    </div>
    {children}
  </main>
  <TabBar />
</div>

3. Componentes por composição

// Meta batida: só trocar os modificadores
<div className={`card goal subject-${i} ${done ? "card--success" : ""}`}>
  <span className="tag">
    <i className="tag__dot" />{name}
  </span>
  <div className={`progress ${done ? "progress--done" : ""}`}>
    <div className="progress__bar" style={{ width: `${pct}%` }} />
  </div>
</div>

Regras de ouro

Um primário por telaSó um botão laranja sólido por tela ou modal. O resto é --secondary ou --ghost.
Laranja é ação ou progressoNão use laranja para decorar. Texto em laranja sobre fundo claro usa --orange-800.
Verde é cumpridoMeta batida, sessão salva, ofensiva validada. Nunca para ação.
Modal fora do app-shellRenderize .modal-backdrop e .toast-region no body (createPortal). O .app-shell usa container queries, o que prende elementos fixos dentro dele.
ÍconesUse lucide-react. Os ícones desta página seguem o mesmo traço de 2px.
Fora do MVPRanking, comparação e desafios (DJ-01 a DJ-03) e edição de sessão (DJ-04) não têm tela aqui, de propósito.

Pontos em aberto que o design já antecipa

O documento deixa três decisões para a implementação. O design assume o seguinte e é fácil trocar: (1) sessão encerrada por timeout mostra o tempo até a última atividade, com o selo "Encerrada automaticamente"; (2) a foto aparece no histórico como miniatura; (3) o aviso de risco da ofensiva existe também dentro do app, além do e-mail do RF-12 (isso é uma sugestão, não está no documento).
